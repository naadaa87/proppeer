# 프롭피어 홈페이지 (proppeer-web)

> 저장소: https://github.com/naadaa87/proppeer-web

부동산 문제 해결 플랫폼 **프롭피어**의 공식 웹사이트입니다.
「프롭피어 홈페이지 제작기획서·기능명세서·제작지시서 최종본」의 **Phase 0(사전 공개 사이트)** 범위를 구현했습니다.

- 빌드 도구 없이 동작하는 **순수 정적 사이트**입니다. (HTML + CSS + JavaScript)
- GitHub 저장소에 올리고 **Cloudflare Pages**에 연결하면 그대로 배포됩니다.
- 핵심 기능인 **3분 문제진단**은 서버 없이 브라우저에서 완결됩니다.

## 3. 로컬에서 먼저 확인하기

파일을 더블클릭해서 열면 `/assets/...` 같은 절대 경로가 동작하지 않습니다.
아래처럼 간단한 서버를 띄워서 확인하세요.

```bash
cd proppeer-web
python3 -m http.server 8080
# 브라우저에서 http://localhost:8080 접속
```

로컬 서버는 `/service` 같은 확장자 없는 주소를 자동 처리하지 않으므로,
확인할 때는 `http://localhost:8080/service.html` 로 접속하면 됩니다.
**실제 배포 후에는 `/service` 로 접속됩니다.** (아래 5-3 참고)

## 4. GitHub에 올리기

받으신 zip 을 풀어 기존 파일에 덮어쓰고 커밋하면 됩니다.

```bash
# 1) 저장소를 받아둔 폴더로 이동 (없다면 먼저 clone)
git clone https://github.com/naadaa87/proppeer-web.git
cd proppeer-web

# 2) zip 안의 proppeer-web 폴더 내용을 이 폴더에 덮어쓰기
#    (파일 탐색기에서 복사·붙여넣기 하셔도 됩니다)

# 3) 변경 내용 확인 후 올리기
git status
git add .
git commit -m "feat: 분야·지역으로 전문가 찾기, 무료 상담 게시판 추가"
git push origin main
```

`main` 에 올라가면 Cloudflare Pages 가 자동으로 다시 배포합니다. 보통 1분 안에 끝납니다.

> 처음 올리시는 경우라면 아래처럼 시작하세요.
>
> ```bash
> cd proppeer-web
> git init
> git add .
> git commit -m "init: 프롭피어 홈페이지"
> git branch -M main
> git remote add origin https://github.com/naadaa87/proppeer-web.git
> git push -u origin main
> ```

**브랜치 전략** (제작지시서 20.1)

| 브랜치 | 용도 |
| --- | --- |
| `main` | 운영 배포. 여기에 병합되면 실제 사이트가 갱신됩니다. |
| `dev` | 작업·검수용. Cloudflare가 미리보기 주소를 자동으로 만들어 줍니다. |
| `feature/*` | 개별 작업 단위 |

> API 키나 결제 키는 **절대 저장소에 커밋하지 마세요.** Cloudflare Pages의 환경변수로만 관리합니다.

## 5. Cloudflare Pages에 연결하기

### 5-1. 프로젝트 생성

1. Cloudflare 대시보드 → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**
2. GitHub 계정을 연결하고 `proppeer-web` 저장소를 선택합니다.
3. 빌드 설정을 아래와 같이 입력합니다.

| 항목 | 값 |
| --- | --- |
| Production branch | `main` |
| Framework preset | **None** |
| Build command | **비워둠** |
| Build output directory | `/` |
| Root directory | 비워둠 |

빌드 과정이 없으므로 1분 안에 배포가 끝나고 `<프로젝트명>.pages.dev` 주소가 생깁니다.

### 5-2. 커스텀 도메인 연결

프로젝트 → **Custom domains** → **Set up a domain** 에서 `proppeer.co.kr` 을 추가합니다.
SSL 인증서는 Cloudflare가 자동 발급합니다.

`www` 와 루트 도메인 중 **하나를 대표로 정해** 나머지는 301로 넘기세요.
(예: `www.proppeer.co.kr` → `proppeer.co.kr`)

### 5-3. ⚠️ URL 규칙 — 가장 주의할 부분

Cloudflare Pages는 정적 배포 시 **`.html` 확장자를 자동으로 정리**합니다.

- `service.html` 파일 → 실제 주소는 `/service`
- `/service.html` 로 요청하면 → `/service` 로 자동 정규화

그래서 다음 두 가지를 반드시 지켜야 합니다.

1. **사이트 안의 모든 링크는 확장자 없이** 씁니다.
   `href="/service"` (○) / `href="/service.html"` (×)
2. **`_redirects` 규칙에도 `.html` 을 쓰지 않습니다.**
   자동 정규화와 겹쳐 **리다이렉트 루프**가 발생합니다.

```
# 올바른 예
/join    /pro    301

# 잘못된 예 (무한 루프 위험)
/service.html    /service    301
```

현재 파일들은 이 규칙에 맞춰 작성되어 있습니다. 링크를 추가할 때만 주의하시면 됩니다.

## 6. 배포 후 바로 해야 할 설정

`assets/js/config.js` **한 파일만** 수정하면 사이트 전체에 반영됩니다.
HTML을 고칠 필요가 없습니다.

```js
channels: {
  email: "hello@proppeer.co.kr",   // 실제 수신 가능한 주소로 변경
  tel:   "02-0000-0000",           // 비워두면 푸터에서 자동으로 사라집니다
},

forms: {
  endpoint: "",                    // 폼 접수 주소 (아래 7번 참고)
},

analytics: {
  ga4: "G-XXXXXXXXXX",             // 넣으면 GA4가 자동 로드됩니다
  cfBeacon: ""                     // Cloudflare Web Analytics 토큰
},

ops: {
  launchLabel: "2026년 하반기 정식 오픈 예정",  // 오픈 시점 문구
  partnerTarget: 33                            // 모집 인원
}
```

앱 출시 후에는 `apps.ios` / `apps.android` 에 스토어 주소만 넣으면 푸터에 링크가 나타납니다.
값이 비어 있으면 해당 항목은 화면에서 자동으로 숨겨집니다.

## 7. 폼 접수 연결하기

지금은 `forms.endpoint` 가 비어 있어서, 신청 버튼을 누르면 **입력 내용이 담긴 메일 초안**이 열립니다.
서버 없이도 접수는 되지만, 실제 운영에서는 아래 중 하나를 연결하는 편이 좋습니다.

**방법 1 — Formspree 등 폼 서비스 (가장 빠름)**

```js
forms: { endpoint: "https://formspree.io/f/xxxxxxx", method: "POST" }
```

**방법 2 — Google Apps Script (스프레드시트에 바로 쌓기)**

스프레드시트에서 확장 프로그램 → Apps Script → 웹 앱으로 배포한 뒤 그 주소를 넣습니다.

**방법 3 — Cloudflare Pages Functions (Phase 1 권장)**

저장소에 `functions/api/submit.js` 를 만들면 `/api/submit` 이 자동으로 생깁니다.
알림 메일 발송이나 DB 저장까지 처리할 수 있습니다.

```js
forms: { endpoint: "/api/submit", method: "POST" }
```

어느 방법이든 전송되는 데이터는 JSON 한 덩어리이며,
`_form`(폼 종류), `_page`, `_at`(접수 시각) 필드가 자동으로 포함됩니다.

## 8. 전문가 데이터 관리 (가장 중요)

전문가 목록·프로필·평점·후기는 모두 **`assets/data/experts.json` 한 파일**에서 나옵니다.
이 파일만 바꾸면 검색·필터·비교·프로필이 함께 갱신됩니다.

### 8-1. 지금은 예시 데이터입니다

파일 맨 위가 이렇게 되어 있습니다.

```json
"meta": { "mode": "sample" }
```

`sample` 인 동안에는 전문가 관련 화면 상단에 **"예시 데이터입니다"** 안내가 계속 표시됩니다.
검증이 끝난 실제 전문가로 교체한 뒤 `"mode": "live"` 로 바꾸면 안내가 사라집니다.

> 실제 전문가가 아직 없다면 `"experts": []` 로 비워두세요.
> "검증된 전문가를 등록하는 중입니다" 안내와 진단·등록 경로가 자동으로 표시됩니다.
> **검증되지 않은 사람을 목록에 올리지 마세요.** 이 서비스가 파는 것이 검증이기 때문입니다.

### 8-2. 전문가 한 명을 추가하려면

`experts` 배열에 항목을 하나 넣으면 됩니다. 주요 항목만 보면 이렇습니다.

| 항목 | 의미 | 주의 |
| --- | --- | --- |
| `slug` | 프로필 주소가 됩니다 (`/experts/{slug}`) | 영문·숫자·하이픈만. 한 번 정하면 바꾸지 마세요 |
| `fields` | 전문 분야 — 필터 기준 | `taxonomy.fields` 에 있는 값만 사용 |
| `problems` | 대응 가능한 문제 — 진단 결과와 연결 | `vacancy` `purchase` `lease` `usage` `cost` `tax` `team` |
| `verification.state` | 검증 상태 7단계 | 확인한 만큼만 적으세요 |
| `verification.items` | 항목별 상태 — `ok`(검증 완료) / `part` / `wait`(검토 중) / `self`(자기 기재) | **확인 안 한 항목은 반드시 `self`** |
| `projects[].v` | 증빙 확인 여부 (`true`/`false`) | 계약·발주 자료로 확인한 것만 `true` |
| `interests` | 이해관계 — 상담 후 제안 가능한 업무 | 있으면 반드시 적으세요 |
| `products` | 상담 상품 ID | `quick15` `deep30` `docs` `second` |
| `reviews` | 후기 — 관계·항목별 점수·본문 | 관계가 확인된 것만 |

추가한 뒤에는 **페이지를 다시 생성해야 프로필이 만들어집니다.** (아래 8-4)

### 8-3. 평점이 표시되는 방식

프롭피어는 **여러 관계의 평가를 하나의 별점으로 합치지 않습니다.**
상담고객·발주자·동료가 볼 수 있는 면이 다르기 때문입니다.

- 목록 카드 → **상담고객 평점만** 표시 (`상담고객 평점 4.8 (3)`)
- 프로필 → 관계별로 나눠서 각각 표시 + 항목별(설명·객관성·일정·예산·소통·문제해결) 막대
- 후기가 없으면 → `—` 와 "상담고객 평점 없음"으로 표시하고, 숫자를 지어내지 않습니다

이 방식은 검증 기준 페이지(`/trust`)에 공개된 정책과 같습니다. 바꾸실 때는 두 곳을 함께 고쳐주세요.

### 8-4. 프로필 페이지 다시 만들기

전문가를 추가·수정한 뒤 아래를 실행하면 프로필 HTML이 다시 생성됩니다.

```bash
node build/gen-site.js
```

생성된 파일을 커밋해 올리면 배포됩니다.
Cloudflare에서 자동으로 처리하고 싶다면 Pages 설정의 Build command 에 `node build/gen-site.js` 를 넣으면 됩니다.

> 검색·필터·비교는 JSON을 직접 읽기 때문에 **재생성 없이도 즉시 반영**됩니다.
> 재생성이 필요한 것은 개별 프로필 페이지뿐입니다.

### 8-5. 후기는 아무나 쓸 수 없습니다

후기 작성은 **결제된 상담이나 확인된 프로젝트 참여가 있는 분**만 가능합니다.
프로필 하단의 후기 작성란은 운영팀이 발급한 확인코드(`PP-0000-0000` 형식)를 받아 요청을 접수하고,
운영팀이 상담 기록과 대조한 뒤 작성 링크를 보내는 구조입니다.

이 절차를 없애고 누구나 쓰게 만들면 후기의 의미가 사라집니다. 유지하시길 권합니다.

## 9. 무료 상담 게시판 운영

무료 상담은 **`assets/data/qna.json`** 에서 나옵니다. 전문가 데이터와 같은 방식입니다.

### 9-1. 어떻게 돌아가나요

정식 오픈 전에는 자동으로 게시되지 않고, **운영팀을 거치는 구조**입니다.

1. 방문자가 `/qna/ask` 에서 질문을 등록합니다 → 폼 접수 경로(7번 참고)로 들어옵니다
2. 운영팀이 해당 분야 전문가에게 전달하고 답변을 받습니다
3. 받은 답변을 `qna.json` 에 넣고 `node build/gen-site.js` 를 실행합니다
4. 질문자에게 답변 등록을 알려줍니다

느려 보이지만 초기에는 이 편이 낫습니다. 답변 품질을 운영팀이 직접 확인할 수 있고, 개인정보가 담긴 글이 그대로 공개되는 사고를 막을 수 있습니다.

### 9-2. 상담글 하나를 추가하려면

```json
{
  "slug": "url-주소가-됩니다",
  "cat": "lease",                    // 대분류 id (experts.json 의 categories 참고)
  "catLabel": "임대차·분쟁",
  "sub": "원상복구·명도",
  "region": "경기",
  "title": "질문 제목",
  "asked": "2026-08-01",
  "answered": "2026-08-03",          // 답변 전이면 빼세요
  "status": "answered",              // 또는 "waiting"
  "views": 0,
  "body": "질문 본문. 줄바꿈은 \n 으로 넣습니다.",
  "answers": [
    { "expert": "lawyer-realestate-seo", "date": "2026-08-03", "body": "답변 본문" }
  ]
}
```

`expert` 값은 `experts.json` 의 `slug` 와 같아야 프로필이 연결됩니다.
답변이 등록되면 해당 전문가 프로필에도 "무료 상담 답변" 목록으로 자동 표시됩니다.

### 9-3. 게시 전 반드시 확인할 것

- **개인정보 제거** — 이름, 연락처, 정확한 주소, 계좌번호, 상대방을 특정할 수 있는 내용
- **답변의 범위 표시** — 확정적 법률·세무 결론이 담기지 않았는지. 답변 끝에 "자료를 확인해야 판단할 수 있다"는 취지가 들어가야 합니다
- **광고성 답변 배제** — 자기 업체를 홍보하는 내용이 아닌지
- 질문 제목은 다듬어도 되지만 **본문은 고치지 않습니다** (안내사항에 그렇게 적어두었습니다)

### 9-4. 상담글이 없으면

`"items": []` 로 두면 "조건에 맞는 상담글이 없습니다" 안내와 질문 작성 경로가 표시됩니다.
지금 들어 있는 7건은 예시 데이터이며, `"mode": "sample"` 인 동안 화면 상단에 안내가 뜹니다.

## 10. 분야 트리와 지역 지도 수정

`assets/data/experts.json` 의 `taxonomy` 안에 있습니다.

| 항목 | 내용 |
| --- | --- |
| `categories` | 분야로 찾기의 6개 대분류와 22개 중분류. `fields` 는 클릭했을 때 걸릴 필터입니다 |
| `regions` | 지역 목록 12개. 전문가의 `regions` 도 여기 값만 씁니다 |
| `mapRegions` | 지도에 표시할 권역 11곳 |

**중분류를 추가할 때**는 `fields` 에 실제 전문가가 등록된 분야를 넣어야 결과가 나옵니다.
비어 있는 분야를 만들면 클릭했을 때 "조건에 맞는 전문가가 없습니다"가 뜹니다.

**지도 모양을 바꾸려면** `build/korea-map.js` 를 수정합니다.
인접 권역이 같은 꼭짓점(`P` 객체)을 공유하도록 만들어져 있어서, 꼭짓점 좌표 하나를 옮기면 맞닿은 권역이 함께 움직입니다. 권역별로 따로 그리면 사이에 빈틈이 생깁니다.

`전국` 으로 등록된 전문가는 **어느 지역을 골라도 함께 표시**됩니다. 전국 단위로 일하는 분들이 지역 검색에서 누락되지 않게 하기 위해서입니다.

## 11. 내용 수정 안내

| 무엇을 바꾸려면 | 어디를 고치나 |
| --- | --- |
| 색상 · 서체 · 여백 · 모서리 | `assets/css/tokens.css` (여기만 고치면 전체 반영) |

| 상담 상품과 가격 | `index.html`, `service.html`, `config.js` 의 `products` |
| 전문가 추가·수정 | `assets/data/experts.json` → `node build/gen-site.js` 실행 |
| 무료 상담 답변 게시 | `assets/data/qna.json` → `node build/gen-site.js` 실행 |
| 분야 트리·지역 | `assets/data/experts.json` 의 `taxonomy` |
| 지도 모양 | `build/korea-map.js` |
| 사례 글 추가 | `cases/` 에 HTML 파일 추가 → `cases/index.html`과 `sitemap.xml`에 링크 추가 |

> **헤더와 푸터는 각 HTML 파일에 들어 있습니다.** 메뉴를 바꿀 때는 모든 파일에서 함께 수정해야 합니다.
> 편집기의 "전체 폴더에서 찾아 바꾸기" 기능을 쓰면 한 번에 처리됩니다.

### 진단 질문을 바꾸려면

`diagnosis.js` 의 `PROBLEMS` 안에서 문제 유형별로 아래 항목을 수정합니다.

| 항목 | 의미 |
| --- | --- |
| `details` / `goals` | 문제별 세부 질문 선택지 |
| `issues` | 결과의 "먼저 확인해야 할 것" |
| `risks` | "확인 전에는 단정할 수 없는 부분" (법률·세무 판단 회피 문구) |
| `seq` | 필요한 전문 분야와 순서 |
| `docs` | 준비 자료 목록 |
| `product` | 추천할 상담 상품 ID |

`risks` 항목은 **삭제하지 마세요.** 플랫폼이 확정적 판단을 하지 않는다는 고지가 이 자리에 들어갑니다.

## 12. 품질 기준 (검수 완료 항목)

- 반응형: 360 · 390 · 768 · 1024 · 1440px 전 구간 가로 스크롤 없음
- 접근성: 키보드 이동, 포커스 표시, 본문 대비 4.5:1 이상, 폼 라벨과 오류 안내, 건너뛰기 링크
- 모션: `prefers-reduced-motion` 설정 시 애니메이션 비활성화
- SEO: 페이지별 title · description · canonical · OG 태그, 사례 글 구조화 데이터(Article), sitemap · robots
- 자바스크립트가 꺼진 환경에서도 모든 정보 페이지는 정상 노출 (진단은 안내 문구로 대체)
- 진단 위저드 7개 문제 유형 전 흐름 동작 확인

**웹폰트** — Pretendard를 CDN(jsdelivr)에서 불러옵니다. CDN 장애 시에도 시스템 한글 폰트로 자연스럽게 대체됩니다.
자체 호스팅으로 바꾸려면 폰트 파일을 `assets/fonts/` 에 넣고 각 HTML의 `<link>` 한 줄을 교체하면 됩니다.

## 13. 표기 원칙 (변경 시 주의)

기획서에서 확정한 원칙이며, 화면 문구를 수정할 때도 유지해야 합니다.

- **검증되지 않은 수치를 쓰지 않습니다.** 회원 수, 거래액, 전문가 수를 임의로 표기하지 않고 "초기 파트너 모집 중"처럼 사실대로 적습니다.
- **AI가 판단하지 않습니다.** 진단 결과는 정리와 안내까지만 하고, 법률·세무·감정·가격 판단은 "확인 전에는 단정할 수 없는 부분"으로 분리합니다.
- **이해관계를 먼저 밝힙니다.** 상담 이후 중개·설계·시공 제안 가능성을 미리 표시합니다.
- **불안을 자극하지 않습니다.** "지금 안 하면 손해" 같은 표현 대신 확인해야 할 것을 담담히 안내합니다.
- **플랫폼의 역할을 고지합니다.** 자격 업무 계약의 당사자가 아니라는 문구를 푸터에서 빼지 마세요.
